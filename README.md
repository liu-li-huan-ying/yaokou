# 窑口

窑炉经营小游戏。当前进度 **M0：配釉台**——一个可单独使用的静态页面，调釉料与烧成曲线，实时看呈色与对目标釉色的色差。

运行时不联网、无后端、无账号、不调用任何模型；呈色与色差全部是本地确定性计算。

## 跑起来

```
npm install
npm run dev        # 本地开发
npm test           # 44 个测试
npm run typecheck
npm run build      # 产物在 dist/，纯静态，可直接托管
```

## 页面

- 10 根滑杆：铁 / 铜 / 钴 / 助熔剂，最高温 / 保温 / 还原强度 / 还原起始 / 冷却速率，窑位温偏
- 左侧 Canvas 画一只带开片的碗，开片条数由冷却与玻化决定，同一参数必得同一纹路（seeded）
- 读数：Lab、sRGB、ΔE2000、评级（珍品 / 正品 / 粗器 / 废品）、玻化度、乳浊度、开片、流釉与变形风险、实际还原度
- 7 个目标釉色：天青、粉青、梅子青、月白、窑变朱、茶叶末、霁蓝
- 「反推配方」用搜索器解出一组能命中目标的参数并回填滑杆

## 呈色模型

铁 / 铜 / 钴各自按饱和曲线溶入玻璃相（`1 - e^(-加入量/半饱和)` × 玻化度），沿一个固定色方向偏移；还原气氛把铁从黄褐方向推向青灰、把铜从铜绿推向铜红。明度按指数吸收 `L = L₀·e^(-Σk·w)` 压暗，彩度经 `tanh` 压缩并随乳浊度衰减。

**这是自洽的虚构化学，不声称复原任何真实工艺。** 之所以能保证"加某味料就沿该料方向单调移动"，是因为上面每一项对单个变量都是单调的，玩家能靠直觉外推——`tests/glaze.test.ts` 逐味料守这条线。

全部数值在 `src/sim/balance.ts`，调平只改这个文件。

## 验证

- **ΔE2000**：期望值取自 `color-diff@1.4.0` 本机实跑，其中三行同时命中 Sharma 等人 2005 年公开测试表的 2.0425 / 2.8615 / 1.0000。另用 300 组 seeded 随机 Lab 对做双实现一致性比对（容差 1e-9）。
  ⚠ `chroma-js` 与 `culori` 的 CIEDE2000 在蓝区高彩度处与公开表不符（分别偏小约 47% 与 9%），因此本项目不用它们当参照。
- **Lab↔sRGB**：D65，锚点 `rgb(255,0,0) ↔ L* 53.2408, a* 80.0925, b* 67.2032`、`rgb(128,128,128) ↔ L* 53.585`，并在 256³ 抽样上验证整数往返无损。
- **可达性**：7 个目标全部存在 ΔE2000 < 3 的烧成解（最差 1.109），由 `src/sim/search.ts` 的坐标模式下降 + 60 次随机重启判定。随机撒点不行——8000 点在 9 维参数盒里太稀，会假报"不可达"。
- **非退化**：随机配方在 Lab 上的分布为 L 10.0–94.2、σ(a\*)=15.25、σ(b\*)=21.29；空配方烧不出任何珍品档。
