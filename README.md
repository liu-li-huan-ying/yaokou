# 窑口

窑炉经营小游戏。你经营一座窑，接单、配釉、装窑、点火、开窑交件。

进度：**M0 配釉台、M1 经营回合、M2 天气与开局修饰符、M3 元进度层（解锁 / 釉料池 / 图纸 / 窑具 / 配方笔记）已完成**，M3 只剩目标色真值。
线上：<https://liu-li-huan-ying.github.io/yaokou/>

运行时不联网、无后端、无账号、不调用任何模型；呈色、色差、经济结算全部是本地确定性计算，同一 seed 必得同一局。

## 跑起来

```
npm install
npm run dev        # 本地开发
npm test           # 104 个测试
npm run typecheck
npm run build      # 产物在 dist/，纯静态
```

## 两屏

**开一窑**（主屏）
- 中央是一座砖砌拱窑，四个窑位就是可点的位置；坯件真的坐在窑膛里
- 左侧釉料案：铁 / 铜 / 钴三个料罐可**上下拖动倒料**（± 留作微调），一根可点击的窑温尺定最高温；保温、还原、冷却收在「看细账」里
- 右侧订单册页：新帖可接可不接，已接的能「装进窑」或「照这单调方」（后者用搜索器解出命中该目标的配方并回填）
- 底部火膛与「点火」：窑门落下封死，器物在窑里从生釉熔向真正烧出的颜色；开窑时窑门升起，器物逐件被抬出窑床，站住了才亮评级
- 顶栏一行小账：窑序 / 现金 / 累计分 / 交付 / 今日天气 / 开局修饰符 / 可复制的局链接
- 顶栏最左是**窑场**：局末结算来的口碑在这里花掉——开釉料罐、买窑具、换窑炉图纸。攒够了才亮那颗点
- 窑位只标「偏热 / 中位 / 很冷」的粗判，不给温度数值——位置知识留给玩家自己记

**配釉台**（工具屏）
- 10 根滑杆全量暴露模型参数，逐味料看颜色连续变化与实时 ΔE2000
- 读数：Lab、sRGB、ΔE2000、评级、玻化度、乳浊度、开片、流釉与变形风险、实际还原度

深链：`?seed=…&m=…&plan=…` 直接开成同一局，`?view=colorizer` 直进工具屏。

## 玩法结构

一局 16 窑上限，**断火（付不起下一窑）即结束**。每窑一套配方、至多 4 件（密檐窑图 3 件）；同一窑里每个位置的温偏不同，所以混色接单必然烧废——按色批窑是这游戏的核心决策。

每局重掷的四件事：订单序列、窑位温偏图、原料与出价、天气（决定降温快慢，进而决定开片轻重）。开局另有 3 选 1 的修饰符（稳火 / 野窑 / 急单 / 还原焰盛），改温偏范围、出价、工期或还原倍率。

**订单册只出本局罐里烧得出的色**：池外的料归零后就不是那个色，出这种单不是难度而是陷阱。所以解锁改变的是"能接哪几色"，见下节。

评级按 ΔE2000 分四档：珍品 <2（溢价 ×1.6）、正品 <6、粗器 <14（折价 ×0.45）、废品（倒罚）。开片 0.2–0.55 是审美加分，>0.8 降一档。
**局末分数只认交付**：`分 = Σ(件分 + 开片加分) − 3 × 违约件数`，下限 0，现金不进分数。

## 元进度

口碑也只在局末结算，同样只认交付：`口碑 = 珍品×4 + 正品×2 + 粗器×1 − 2×违约件数`，下限 0。它存在 `localStorage` 的 `yaokou.meta.v1` 明文 JSON 里，你自己能打开改（坏档退回默认而不是崩）。

窑场里六样东西，**全部只加选项、不加数值上限**：

| 花口碑买 | 买到的是什么 |
|---|---|
| 铜料 40 / 钴料 70 | 多一罐可选的料，不是把铁的上限抬高 |
| 匣钵 55 / 支钉 35 | 流釉风险 ×0.5 / 变形风险 ×0.7，各管各那一路 |
| 直焰窑图 80 | 窑位温偏改成前热后冷的单调梯度——位置好记了，幅度没变 |
| 密檐窑图 95 | 窑位间温差收窄一半，代价是少一个窑位（4 → 3） |

已解锁的釉料池不等于本局能用的料：**每局按 seed 从池里掷一个子集**（铁保底，其余各 55%，至少 2 罐），没掷到的料罐显示「未开罐」、配方值强制为 0，所以锁住的料绝不会偷偷影响呈色。图纸与窑具也从换局起才上身——中途买的，本局火膛那行小字不会骗你说已经用上了。

**七色一色一方，方子写死在 `src/sim/targets.ts`。** 每份"传世方子"是在"只准用那几味料"的约束下搜出来的最优解（推导工具：`tests/author-glazes.test.ts`），所以七色全部落在珍品档，招牌料也读得出来：

| 色 | 招牌料 | 白手能接 |
|---|---|---|
| 月白 | 素釉，不加料 | ✓ |
| 天青 | 铁 0.73，还原 | ✓ |
| 梅子青 | 铁 7.25，浓 | ✓ |
| 粉青 | 铜 0.36，**氧化**出绿 | 要铜罐 |
| 窑变朱 | 铜 3.69，**还原**出红 | 要铜罐 |
| 茶叶末 | 铁 8 + 铜 0.89 并用 | 要铜罐 |
| 霁蓝 | 钴 2，一入即蓝 | 要钴罐 |

于是解锁的形状是准的：**白手三色 → 开铜六色 → 开钴七色**（`tests/reachability.test.ts` 把这条钉死了）。方子必须是数据而不能是运行时搜索，理由也在这：搜索器每回可能顺手多用一味料，那味料一旦不在罐里，"这单烧不烧得出来"的判据就会随 seed 漂。

**配方笔记**也在窑场里：把案上现在的四味料、最高温、还原强度记成一条带名字的方子，跨局留着（上限 12 条）。「用这方」时本局没掷到的料仍按 0 落回案上，笔记不能替你绕过釉料池。存档是明文 JSON，所以笔记要逐条验：少字段、非数、空名一律丢掉，绝不让 NaN 进配方。

## 呈色模型

铁 / 铜 / 钴各自按饱和曲线溶入玻璃相（`1 - e^(-加入量/半饱和)` × 玻化度），沿一个固定色方向偏移；还原气氛把铁从黄褐推向青灰、把铜从铜绿推向铜红。明度按指数吸收 `L = L₀·e^(-Σk·w)` 压暗，彩度经 `tanh` 压缩并随乳浊度衰减。

**这是自洽的虚构化学，不声称复原任何真实工艺。** "加某味料就沿该料方向单调移动"由构造保证（每一项对单个变量都单调），玩家能靠直觉外推——`tests/glaze.test.ts` 逐味料守这条线。

七个目标色的 Lab 是**按模型真能烧到的样子校准过的设计值**：先定"这色该由哪味料当家"，再在只给那味料的约束下搜出最优解，把 Lab 收到那个解上。反过初版那套 Lab（天青 b=+6、月白 b=+3）模型根本够不到，硬留着就只能让搜索器去借别味料凑，釉料池的判据因此会漂。

全部数值在 `src/sim/balance.ts` 与 `src/sim/run.ts` 的 `ECONOMY`，调平只改这两处。

## 验证

- **ΔE2000**：期望值取自 `color-diff@1.4.0` 本机实跑，其中三行同时命中 Sharma 等人 2005 年公开测试表的 2.0425 / 2.8615 / 1.0000；另用 300 组 seeded 随机 Lab 对做双实现一致性比对（容差 1e-9）。
  ⚠ `chroma-js` 与 `culori` 的 CIEDE2000 在蓝区高彩度处与公开表不符（分别偏小约 47% 与 9%），因此本项目不用它们当参照。
- **Lab↔sRGB**：D65，锚点 `rgb(255,0,0) ↔ L* 53.2408, a* 80.0925, b* 67.2032`、`rgb(128,128,128) ↔ L* 53.585`，256³ 抽样上整数往返无损。
- **可达性**：7 个目标全部存在 ΔE2000 < 3 的烧成解（不限料时最差 0.072），由 `src/sim/search.ts` 的坐标模式下降 + 60 次随机重启判定。随机撒点不行——8000 点在 9 维参数盒里太稀，会假报"不可达"。
- **非退化**：随机配方 Lab 分布 L 10.0–94.2、σ(a\*)=15.25、σ(b\*)=21.29；空配方（不加任何料）只蒙得住月白一色，其余六色一律出不了珍品。
- **假循环检查**（200 局 × 5 策略 × 两档釉料池，同一 seed 跨策略配对，按 seed 抽开局修饰符）：

  | 策略 | 白手 平均分 / 窑数 / 破产 | 满罐 平均分 / 窑数 / 破产 |
  |---|---|---|
  | 躺平（每窑烧空） | 0.0 / 4.0 / 100% | 0.0 / 4.0 / 100% |
  | 乱烧（随机配方） | 11.1 / 2.3 / 100% | 3.5 / 1.3 / 100% |
  | 一法到底（固定配方） | 63.6 / 7.1 / 86% | 20.8 / 2.9 / 99% |
  | 按单求解 | 308.6 / 15.5 / 4% | 326.0 / 15.9 / 1% |
  | 看行情应变 | 310.8 / 15.1 / 8% | 325.4 / 15.9 / 2% |

  赢家分布：白手档 看行情应变 117 / 按单求解 68 / 一法到底 3 / 乱烧 2 / 躺平 0；满罐档 看行情应变 100 / 按单求解 95 / 躺平 0。
  两档里固定一套配方都压不倒应变，躺平结构性地一件不交——循环不是假的。
  **解锁的效果也在这张表里**：会求解的策略从 309 涨到 326，破产从 4-8% 降到 1-2%；而 `一法到底` 反而从 63.6 **跌到** 20.8——订单册一宽，抱着一套方子的人错得更多。
- **一色一方不通用**：任取一色的传世方子，其余六色一律出不了珍品（ΔE ≥ 2）。这条是"按色批窑"这个核心决策成立的前提，若一份方子能蒙中两色，混单就不亏、窑位与池子都失去意义。
- **池子决定订单册**：`fillableTargets(['fe'])` 恰好 3 色、加铜 6 色、加钴 7 色，且每色的招牌料互不相同。
- **元进度接线**（`tests/meta.test.ts`、`tests/m3.test.ts`）：口碑公式、釉料池保底且绝不冒出未解锁的料、窑具倍率各管一路（归零时逐件核对评级 = 无缺陷路径的评级，拉满时件件废品）、密檐窑图确实少装一件、图纸只改形状不改量程；配方笔记逐条验坏档、上限 12 条、用时未掷到的料归零。

## 数据来源

当前 7 个目标色是**设计值**。原计划 M3 用大都会博物馆开放藏品 API 采样真值，但实测**它的 search 端点不可靠**：多词查询（`sancai`、`blue and white`、`oxblood`）返回 0 条，同一句 `glazed ceramic` 上午返回 66、下午返回 0，加 `departmentId` 反而更少。按 `objectID` 直取单件是稳定的（`objects/53002` → `isPublicDomain: true` 并给出原片地址，原片可下载）。

所以 M3 的取数改成**人工给定 objectID 清单**，不再指望检索枚举。取到后仍是构建期一次性预烘焙进仓库，运行时不联网。

## 已知不足

- **深色对窑位温偏过敏感，而价格没按这个风险差来定。** 实测同一份方子在 ±40℃ 温偏下的 ΔE：月白 ≤1.3、粉青 ≤1.9、天青 ≤2.7、霁蓝 ≤4.5，几乎免疫；梅子青 −40℃ 就飙到 27.5（废品）、茶叶末 21.8、窑变朱 15.3。可出价是 月白 22 / 梅子青 42 / 茶叶末 46——按"落在可用窑位的比例"折一下期望值，两个硬色反而比白烧月白还便宜，理性玩家会躲开它们。要么给硬色提价，要么重寻一份在温偏带里更平的方子（`tests/author-glazes.test.ts` 换个目标函数就能做）。
- **难度整体偏软了**：池子与方子校准之后，两个胜任策略的破产率掉到 1-8%、平均 15-16 窑，几乎人人跑满 16 窑上限。假循环检查的判据（固定策略压不倒应变、躺平一件不交）仍然成立，但"这一局会不会输"的压迫感需要重新调。
- **落渣这一类缺陷还没做**，现在缺陷只有流釉与变形两种，匣钵与支钉因此各压一路、没有共同的对手。
- 天气目前只影响开片轻重，不影响成品率。
- 解锁了全部六样之后元进度就到顶，之后只剩每局掷釉料池这一层变化。
- 两档对照表给的是"给定池子"的上界；机器人仍然不会自己攒口碑、买解锁、挑图纸，所以元进度层的**节奏**（几局能开满、开了之后打法该不该变）还没被模拟过。
